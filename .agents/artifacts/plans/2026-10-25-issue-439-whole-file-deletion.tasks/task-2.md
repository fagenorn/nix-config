# Task 2: The generator replaces an oversized whole-file deletion with bounded evidence

Spec § Evidence shape, § Which records qualify, § Generator self-check, § Blob lookup reads a literal path, § Manifest version and § Documentation, per D1–D7, D11, D12 and D14. `actual_inputs_from_trees` reads each record's operation once per range. An oversized record whose operation is `D`, and which the EF designer builder did not claim, becomes a `whole-file-deletion` entry built from the base blob. The existing fit guard decides as it does for EF. The candidate builder's kind check becomes a closed set, the shared tree lookup reads literal paths, and `python/README.md` gains one paragraph.

**Interfaces:**
- Consumes: Task 1's validator. The CLI publishes through `artifact-budget check --kind review-package`, which must accept `whole-file-deletion` entries.
- Produces, in `agent_tools.review_actual`:
  - `RECORD_OPERATIONS: tuple[str, ...] = ("A", "M", "D", "T", "R100")`
  - `GENERATED_EVIDENCE_KINDS: tuple[str, ...] = ("ef-core-migration-designer", "whole-file-deletion")`
  - `_record_operations(raw: bytes, paths: list[str]) -> tuple[str, ...]`
  - `_blob_identity(blob: tuple[str, bytes]) -> dict[str, object]`
  - `_whole_file_deletion_evidence(repo: Path, base: str, path: str, source_diff_bytes: int) -> dict[str, object]`

**Invariants:**
- `RECORD_POLICY`, `PACKING_POLICY`, their digests and `git_diff`'s allowed views do not change. `("--name-status", "-z")` is already an allowed view.
- The name-status view is read once per `actual_inputs_from_trees` call, before the packing-choice loop, and aligned with the name-only paths (D1, D14).
- An oversized record gets evidence only from `_ef_designer_evidence`, or, when that returns `None` and the operation is `D`, from `_whole_file_deletion_evidence`. The fit guard (`len(compact) <= limits.member_max_bytes`) then decides, and there is no second fallback (D5). `A`, `M`, `T` and `R100` records keep their whole record.
- `_whole_file_deletion_evidence` reads only the base tree. It returns `{"path", "kind": "whole-file-deletion", "source_diff_bytes", "base": {**_blob_identity(blob), "line_count"}, "head": None}`. `line_count` is `raw.count(b"\n")`, plus 1 when `raw` is non-empty and does not end in `b"\n"` (D4). A `D` path with no base blob raises `GenerationError("deleted path has no base blob")`.
- `_ef_designer_side` builds its first three keys with `{**_blob_identity(blob), …}`, so EF output is byte-identical.
- `_blob_at` runs `git --literal-pathspecs -C <repo> ls-tree -z <commit> -- <path>` (D11). Its other checks are unchanged.
- `_build_candidate` keeps every evidence check and replaces only `evidence.get("kind") != "ef-core-migration-designer"` with `evidence.get("kind") not in GENERATED_EVIDENCE_KINDS`. Tuple membership compares by equality, so an unhashable kind is refused and does not raise `TypeError` (D6).
- The manifest version rule is unchanged: initial context plus evidence gives v2 (D7).

1. Put `RECORD_OPERATIONS` and `GENERATED_EVIDENCE_KINDS` after `PACKING_POLICY_SHA256`. Use the values given under Interfaces.
2. Put `_record_operations(raw, paths)` after `_changed_paths`, with the docstring: "Each record's `--name-status -z` operation, in the order of the name-only `paths`." It works as follows:
   - Empty `raw` gives `()`.
   - Otherwise split on `b"\0"`. The last item must be `b""`, else raise `GenerationError("malformed Git status list")`. Drop that item.
   - Walk the items. Each operation is ASCII and in `RECORD_OPERATIONS`; on a decode error or any other value, raise `GenerationError("unsupported Git record operation")`.
   - The operation is followed by two non-empty names for `R100` and one for every other operation. A short or empty name raises `"malformed Git status list"`.
   - The destination is the last name, decoded as strict UTF-8; a decode error raises `GenerationError("Git path is not UTF-8")`. It must equal `paths[i]` at the same index. A mismatch, or more or fewer records than `paths`, raises `GenerationError("Git status does not match paths")`.
3. In `actual_inputs_from_trees`, after the numstat coverage check and before the packing-choice loop, add `operations = _record_operations(git_diff(repo, base_tree, head_tree, "--name-status", "-z"), paths)`. Loop with `for path, operation, chunk in zip(paths, operations, chunks):`. In the oversize branch, after `item = _ef_designer_evidence(…)`, add `if item is None and operation == "D": item = _whole_file_deletion_evidence(repo, base_tree, path, len(chunk))`. The existing `if item is not None:` fit guard follows unchanged.
4. Put `_blob_identity(blob)` before `_ef_designer_side`. It returns `{"blob_sha": sha, "bytes": len(raw), "content_sha256": hashlib.sha256(raw).hexdigest()}`. `_ef_designer_side` returns `{**_blob_identity(blob), "migration_id": …}` and keeps its remaining keys.
5. Put `_whole_file_deletion_evidence(repo, base, path, source_diff_bytes)` after `_ef_designer_evidence`, with the docstring: "Bounded evidence for a path the range deletes outright: its base blob, and a head that is null because the status is `D`." Its body follows the Invariants.
6. In `_blob_at`, change the argv to `["git", "--literal-pathspecs", "-C", str(repo), "ls-tree", "-z", commit, "--", path]`.
7. In `_build_candidate`, change only the kind comparison, as given under Invariants.
