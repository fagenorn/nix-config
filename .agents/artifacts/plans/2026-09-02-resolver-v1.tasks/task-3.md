# Task 3: Projection rendering and `write-projections`

**Files:**
- Modify: `home/common/agent-skills/scripts/resolve-project.py`
- Test: `home/common/agent-skills/tests/test_resolve_project.py`
- Create (generated): `AGENTS.md` (repository root)
- Modify (generated line appended): `CLAUDE.md` (repository root)

**Interfaces:**
- Consumes, from Tasks 1–2: `SCHEMA_VERSION = 1`; `PROJECTION_KINDS = ("generated_file", "managed_import")`; `AGENT_IDS`; `class ContractError(Exception)` with `code`, `repair_id`, `violations`; `discover_root(repo_root) -> Path`; `load_contract(root) -> dict`; `validate_contract(source) -> list[dict]`; `emit_json(value) -> int`; `emit_error(code, repair_id, violations) -> int`; `main(argv=None) -> int`, which carries the `resolve` subparser only; **this task registers the `write-projections` subparser for the first time** (B-001). A projection entry is exactly `{"id", "agent", "kind", "target", "source"}` with repository-relative `target` and `source`.
- Produces, for Task 4: `render_projection(entry: dict, source_bytes: bytes) -> bytes` returning the exact bytes a `generated_file` target must hold, or the exact single managed line (with its trailing newline) a `managed_import` target must contain; `read_projection_source(root: Path, entry: dict) -> bytes` raising `ContractError("invalid_contract", "contract.projections.source_missing", …)` when the source file is absent; and `projection_status(root: Path, entry: dict) -> str` returning one of `"in_sync"`, `"missing"`, `"stale"`.

**Invariants:**
- Rendering is a pure function of (source bytes, projection id, schema version) — no timestamp, digest, hostname, or path outside the entry enters the output.
- A `generated_file` target holds exactly: the header line, one blank line, then the source bytes unchanged.
- A `managed_import` target contains the managed line exactly once, as a complete line; the rest of the target is authored and is never rewritten.
- `write-projections` writes only what differs: a target already in sync is left byte-identical with an unchanged mtime.
- Every write is atomic — a temporary file in the target's own directory, then `os.replace`.
- `write-projections` refuses a `managed_import` target holding the managed line more than once, with `invalid_projection` and `projection.<id>.stale`; it never deletes or rewrites authored content (D17).
- A missing projection *source* is `invalid_contract`, never drift.

```python
    """Contract: the exact bytes a generated_file target must hold, or the
    exact single managed line (with its newline) a managed_import must contain."""
```

`read_projection_source` reads `root / entry["source"]` as bytes and, on `OSError`, raises `ContractError("invalid_contract", "contract.projections.source_missing", [{"pointer": f"/projections/{entry['id']}/source", "message": …}])`.

`render_projection` dispatches on `entry["kind"]` and raises on the default branch:
- `generated_file` → `GENERATED_HEADER_TEMPLATE.format(source=entry["source"], version=SCHEMA_VERSION).encode("utf-8") + b"\n\n" + source_bytes`.
- `managed_import` → `(MANAGED_IMPORT_TEMPLATE.format(source=entry["source"]) + "\n").encode("utf-8")`.

Neither branch consults the clock, the environment, or anything outside `entry` and `source_bytes`.

- [ ] **Step 4: Implement comparison and `write-projections`**

Add `projection_status(root, entry) -> str` returning exactly one of the closed set `"in_sync"`, `"missing"`, `"stale"`. Every call site dispatches explicitly over all three and raises on any other value rather than branching on "not `in_sync`" (SF-003):
- `generated_file` — target absent → `"missing"`; target bytes equal to the rendered bytes → `"in_sync"`; otherwise `"stale"`.
- `managed_import` — target absent → `"missing"`; the managed line appears exactly once among the target's lines → `"in_sync"`; zero occurrences → `"stale"`; more than one occurrence → `"stale"`.

Register the `write-projections` subparser, accepting `--repo-root`, and implement its body. It resolves the root, loads and validates the contract (Task 1's path, so a broken contract still refuses first), then, for each entry in `contract["projections"]` in source order:

- `in_sync` → record `{"id": entry["id"], "action": "unchanged"}` and touch nothing.
- `generated_file` that is `missing` or `stale` → write the rendered bytes atomically and record `"written"`.
- `managed_import` that is `missing` → create the target holding exactly the managed line, atomically, and record `"written"`.
- `managed_import` that is `stale` with **zero** occurrences → read the existing bytes, append the managed line (prefixing a newline when the existing content does not end in one), write atomically, record `"written"`.
- `managed_import` that is `stale` with **more than one** occurrence → collect a violation `{"pointer": f"/projections/{entry['id']}", "message": …}` and write nothing to that target (D17).

After the loop, when the violation list is non-empty, sort it by pointer and raise `ContractError("invalid_projection", f"projection.{first_id}.stale", violations)` — where `first_id` is the id in the first violation's pointer — so a refusal is emitted instead of the summary. Any target already written before the refusing entry keeps its new bytes; the refusal names only the entries it could not resolve. Otherwise emit `{"projections": [{"id": …, "action": …}, …]}` in source order and return 0.

Atomic write helper: create the temporary file with `tempfile.NamedTemporaryFile(dir=<target's parent>, delete=False)`, write the bytes, `flush`, close, then `os.replace(tmp, target)`; remove the temporary file in a `finally` when the replace did not happen.
