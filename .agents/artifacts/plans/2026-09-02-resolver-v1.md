# Resolver v1 Implementation Plan

> **For agentic workers:** execute this plan with the `sdd` skill — one implementer
> per task, reviewed between tasks. Steps use `- [ ]` checkboxes.

**Goal:** Give this repository one authored project contract, one fail-closed read-only `resolve` that returns the versioned `ResolvedProject` snapshot, two generated native entry projections with a drift check, and one workflow skill entry that consumes the resolver instead of the fail-soft binding helper.

**Architecture:** A single standard-library Python script, `home/common/agent-skills/scripts/resolve-project.py`, installed as `~/.agents/bin/resolve-project`, owns root discovery, contract loading, one-pass structural validation, path normalization, capability readiness computation, projection rendering, and three subcommands (`resolve`, `check-projections`, `write-projections`). The authored source `.agents/project.json` is the only input; `.agents/instructions/bootstrap.md` is the only instruction source, projected into a wholly generated root `AGENTS.md` and a single managed import line inside the otherwise-authored root `CLAUDE.md`. `writing-plans` is the first skill entry migrated onto the snapshot.

**Tech stack:** Python 3 standard library (`argparse`, `json`, `pathlib`, `shutil`, `os`), `unittest` driven by subprocess against temporary roots, Home Manager / Nix (`home/common/agent-skills/default.nix`), Just.

## Global Constraints

- The authoritative design is `.claude/specs/2026-09-02-resolver-v1-design.md`. Cite D1–D17 by ID; never restate their rationale in code, tests, or commits.
- The eleven capability names are exactly `tracker`, `worktrees`, `knowledge.context`, `knowledge.standards`, `knowledge.architecture`, `knowledge.hints`, `verification`, `review.plan`, `review.code`, `release`, `deploy`. No twelfth name is added (D9).
- The six binding namespaces are exactly `vcs`, `tracker`, `paths`, `commands`, `workflow`, `deploy`.
- Capability states are exactly `available`, `unsupported`, `blocked`. Authored support values are exactly `supported`, `unsupported`. Error codes are exactly `not_onboarded`, `invalid_contract`, `unsupported_schema`, `invalid_projection`, `capability_unavailable`, `resolver_failure`. Reason codes are exactly `tracker_cli_missing`, `vcs_worktree_unsupported`, `knowledge_path_missing`, `command_missing`. Projection kinds are exactly `generated_file`, `managed_import`. Agent ids are exactly `claude`, `codex`.
- Every dispatch over one of those closed sets raises on its default branch rather than falling through (the bar, *Fail loud*).
- `schema_version` is the integer `1` for both the authored source and the snapshot; any other integer is `unsupported_schema` (D8).
- `ResolvedProject` has exactly four top-level members: `schema_version`, `project`, `bindings`, `capabilities`. No timestamps, digests, provenance, or source path ever appear in the output.
- No project policy is ever defaulted. A missing, unexpected, or malformed key is a violation, never an implied value; omission of a capability declaration is never an implied state.
- Success output is `json.dump(..., sort_keys=True, separators=(",", ":"))` plus a trailing newline on stdout, exit 0 — the `workflow-state` convention.
- Structural failure prints exactly one JSON object `{"error": {"code", "repair_id", "violations"}}` on **stdout** and exits 2, with `violations` non-empty and sorted byte-wise ascending by `pointer`. No partial snapshot member accompanies an error. Argparse usage errors also exit 2 but print no JSON (D12, D16).
- `invalid_contract` collects every shape violation in one pass before failing; it never aborts on the first.
- All authored paths are repository-relative. An absolute path, a leading `/`, or a `..` segment is an `invalid_contract` violation.
- Every executable invocation is a `commands` entry addressed by a stable id; `workflow.verification` holds a list of ids, `workflow.review.plan`, `workflow.review.code`, `workflow.release` and `deploy.command` hold one id or `null`. An id absent from `commands` is an `invalid_contract` violation. A `commands` entry is `{"argv": [...], "cwd": "<repo-relative>", "env": ["NAME", ...]}`; `env` holds variable names only, never values, and no entry carries opaque shell text (D13).
- `resolve` and `check-projections` are strictly read-only: they open no file for writing, create no directory, and run no subprocess — including `git`. Readiness is decided from the filesystem and `PATH` alone. `write-projections` is the sole writer and is a no-op when everything is in sync.
- "Resolves on `PATH`" means `shutil.which`, plus an executable-bit check at the named path when `argv[0]` is absolute or relative.
- A capability declared `supported` whose bindings are structurally incomplete is `invalid_contract`, never `blocked` (D6). A capability declared `unsupported` imposes no requirement on its bindings and has no prerequisite evaluated.
- Projection staleness is a structural error on `resolve` (`invalid_projection`, no snapshot), never a capability state (D10).
- Writes are atomic: temp file in the same directory plus `os.replace`.
- `resolve-bindings` is neither deleted nor modified; `.claude/skills.config.json` stays in place and the resolver never reads it (D2). Only `writing-plans` migrates (D3).
- No glossary, CONTEXT map, or ADR file is created (D14). No new `just` recipe and no CI change (D15).
- Python standard library only. Sign commits normally; never pass `-c commit.gpgsign=false` or `--no-gpg-sign`. Append `Co-Authored-By: Claude Fable 5.1 <noreply@anthropic.com>` to every commit message.

## Test seams

- **Subprocess the script against a temporary repository root and parse its stdout** — the primary seam, established by `tests/test_resolve_bindings.py` and `tests/test_workflow_state.py`. Add no other seam.
- **One narrow exception, `ResolverFailureTest` only (D23).** That single test loads the module by path and monkeypatches `load_contract` to raise, because `resolver_failure` is the catch-all for exceptions no external input can reach: every reachable file, encoding, JSON and shape failure is already classified into another code, so no subprocess fixture can exercise it. No other test imports the resolver.
- **`home/common/agent-skills/tests/test_resolve_project.py`** is the resolver's whole suite, wired into the `agent-workflow-tests` recipe.
- **The repository's own committed `.agents/project.json`** is the drift gate: resolving it inside the suite fails whenever a projection has been hand-edited without regeneration (D15).
- **`home/common/agent-skills/tests/test_workflow_skill_contracts.py`** is the skill-prose seam for the migrated `writing-plans` entry.
- **`just build`** is the publication seam for the Nix-installed `.agents/bin/resolve-project`.
