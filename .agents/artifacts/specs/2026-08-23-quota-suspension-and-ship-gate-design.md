# Quota suspension and ship-gate standing authorization — design

Primary issue: fagenorn/nix-config#101 (checkpoint quota-wall terminations, one-command re-entry), extended with ship-phase authorization. Companion filing map in Out of scope.

## Problem

`/from-issue --auto` and `/orchestrate-issues` rarely drive an issue to merged without a human acting as the retry mechanism. Over 14 days across three consuming repos: ~50 ledgered runs produced 4 autonomous merges; 1,251 usage-limit kill events landed in 166 transcripts; 554 late-but-genuine finishes were refused against reaper stubs. Runs overwhelmingly die with spec, plan, and review complete but execution or shipping unstarted.

The root cause is that the lifecycle layer treats *environmental* interruption as *semantic* failure. The attempt budget is wall-clock, so a quota outage consumes it while nothing works. Expiry writes a terminal record; a graceful owner stop is unretryable while silent expiry is retryable, so agents learned to let the deadline fire. Two terminal records lock the issue behind a human-typed authorization phrase, and each unlock fragments history into a new unlinked run. Separately, runs that survive to shipping hit a per-action permission wall at push/PR-open/merge — the two skill texts contradict each other about whether standing authorization exists — and one issue that stalls freezes every dependent behind it. The ledger never learns when a human finishes the work by hand, so the next run reads stale state as authoritative.

## Solution

Introduce a **suspension model** in the durable workflow-state control plane: environmental terminations (quota, transport, human gate, external wait, unknown/expiry) become a non-terminal `suspended` state that is resumable with one idempotent command, consumes no attempt, and needs no authorization phrase. Terminal states are reserved for semantic outcomes. At acquisition, the control plane reconciles the ledger against the forge through the existing observation ladder, and successor runs link to their predecessors. At ship time, the existing fail-closed permission guard is extended so pushing, PR-opening, and protection-checked merging carry standing authorization in qualifying repos — with `suspended(human_gate)` as the graceful fallback everywhere else. The skill prose is rewritten to state that single truth once.

## Decisions

**Suspension state.** The attempt lifecycle gains a non-terminal `suspended` state carrying `blocked_on ∈ {usage_limit, transport, human_gate, external, unknown}`. Owners get a first-class suspend verb for graceful exits (approaching a quota window, waiting on a human-only gate). The lazy reaper — the existing next-touch stamping mechanism, unchanged in trigger — demotes an expired active attempt to `suspended(unknown)` instead of writing a terminal stop. An owner-recorded `stopped` remains terminal and is now reserved for genuinely semantic stops (invalid issue, unfixable blocker); the policy that punished graceful stops disappears because environmental exits no longer go through `stopped` at all.

**Resume semantics.** Resuming a suspended attempt requires no authorization phrase, consumes no attempt, grants a fresh full `agentBudgetMinutes` window, and appends a resume launch event to the attempt's existing launch list. Re-entry is idempotent: resuming an attempt that is not suspended is a no-op that reports current state; running the re-entry command twice neither duplicates work nor advances phase twice. Anti-zombie bound: the third consecutive resume that ends without advancing the recorded phase escalates the attempt to a terminal, synthetic-sourced stop. Suspension output and progress output print the exact one-line re-entry command (#101's demo).

**Attempts and lineage.** The two-semantic-attempt cap and the `new_run` human escape hatch are unchanged — resumes are free, so the cap stops being the bottleneck. A run created via `new_run` records a `prior_run` link to its predecessor so an issue's history is one chain, not N unlinked run directories.

**Forge reconciliation.** The acquisition observation ladder gains a forge observation: the state of any PR for the issue's branch (open/merged/closed, URL, merge SHA), supplied by the acquiring owner like every other observation. The control plane reconciles the ledger before granting ownership — a merged PR closes out the stale record instead of the next owner rediscovering it by hand. A late owner-sourced finish may supersede only a *synthetic* record (reaper-written); it may never overwrite another owner-recorded terminal result, preserving the write-once guarantee where it means something.

**Outcome reporting.** The cost reporter's outcome heuristic classifies every `suspended` state as interrupted, never abandoned (#101 criterion) — an owner killed mid-flight by a quota wall cannot record its own cause, so the reaper's `suspended(unknown)` must count the same as an owner-recorded `usage_limit` or `transport`.

**Ship-gate standing authorization.** The existing fail-closed pre-tool-use guard is extended: in any repo whose origin resolves to a `fagenorn/`-owned repository it authorizes pushing a non-default branch (no force or delete flags) and opening a PR whose base is the integration branch. The merge grammar generalizes from one hardcoded repository to the *current repo's origin* — same ownership check as above — still requiring live admin-enforced branch protection with at least one required status check. Anything that fails these checks fails closed, and the owner suspends `blocked_on: human_gate` instead of dying — a later approval resumes without penalty. The guard matches only command-position tokens: heredoc bodies, string literals, and comments can never trigger it (today it substring-matches and rejects innocent commands whose text mentions a guarded verb).

**Single prose truth.** ship-issue and from-issue both state the same rule: standing authorization exists exactly where the guard grants it; elsewhere the owner suspends at the gate. The contradiction (one text claiming blanket standing auth, the other claiming per-action gating) is removed. The handoff concept stays distinct from suspension — handoff is the deliberate context rollover with a handoff document; suspension is the environmental pause with none — and the resume acceptance gate is widened so orchestrated runs can resume a Phase-0 handoff (the gap that stranded whole orchestration runs).

**Orchestration re-entry.** Re-invoking the orchestrator over a run with suspended attempts sweeps and auto-resumes them — one retyped command instead of one per issue, and still no always-on supervisor, honoring #101's exclusion. Deadline-less `wait:external` is outlawed: a control wait must carry a concrete deadline, or control returns to the user with a stated reason.

## Test seams

Existing seams only; no new ones.

- **Workflow-state suite** (`just agent-workflow-tests`, fixture-transcript pattern per #101): suspension taxonomy, reaper demotion, resume idempotency and fresh window, anti-zombie escalation, attempt-cap unchanged, `prior_run` lineage, forge reconciliation, narrow supersede rule, re-entry command output.
- **Skill-contract suite** (same runner): the single authorization statement present in both skills, no deadline-less waits taught, suspend/handoff distinction, re-entry wording in progress output templates.
- **Permission-guard suite** (the repo's Python guard tests): acceptance and rejection grammars for push/PR-create/merge, ownership and protection checks fail-closed, and non-matches for heredoc/string-literal mentions of guarded verbs.
- **`just build`**: the generated settings artifact still resolves to exactly one artifact with the extended allow surface.

## Out of scope

- An automatic restart supervisor or daemon (#101 explicitly excludes it; re-entry stays human-initiated and cheap).
- Codex bridge fixes — per-operation reviewer timeouts, reviewer PATH, sandbox-limit findings noise, and reviewer blocking-verdict calibration → **new issue** ("Codex reviewer bridge: budgets, PATH, and finding hygiene").
- Workflow scratch placement and cleanup → **#102 already filed**; the sdd write-root discipline (state under the ledger repo root, never cwd) is proposed as an added criterion on #102, not a new issue.
- Exposing orchestrate-issues to Codex and investigating the missing Superpowers marketplace entry in the Codex config → **new issue**.
- The four prose-error classes in #99, loud bindings resolution (#100), and cost telemetry format (#97) — already tracked.
