## Findings across the month

### What works

The harness can carry a well-bounded issue through implementation, review, CI, merge, closure, and cleanup. Across the projected ledgers, merged outcomes are common: Arcwave 6 of 12 attempts, Argus 3 of 23, nix-config 9 of 26, and Nodo 71 of 156. Those are attempt counts, not issue-level completion rates, but they show that the main path is real rather than aspirational. Recent nix-config work also landed meaningful platform pieces: the strict project resolver ([#118](https://github.com/fagenorn/nix-config/issues/118)), Codex ship handoff ([#119](https://github.com/fagenorn/nix-config/issues/119)), structured cost/evidence output ([#120](https://github.com/fagenorn/nix-config/issues/120)), and conformance registry ([#122](https://github.com/fagenorn/nix-config/issues/122)).

Failure handling generally preserves useful work. The [#121](https://github.com/fagenorn/nix-config/issues/121) attempt retained a clean 30-commit branch after Tasks 1–6, 873 passing tests, and a successful build; its terminal failure records the package cap rather than misclassifying the implementation. Nodo [#1519](https://github.com/elevenyellow/nodocom/issues/1519), [#1295](https://github.com/elevenyellow/nodocom/issues/1295), and [#1318](https://github.com/elevenyellow/nodocom/issues/1318) later merged after failed first attempts, showing that retained work can be recovered.

The project contract itself is substantially safer than the legacy bindings path. `resolve-project.py` closes read/parse/schema errors (`home/common/agent-skills/scripts/resolve-project.py:62-69`, `:372-399`), detects generated-projection drift (`:1032-1069`), and exposes only `resolve`, `check`, and `write-projections` on main (`:1259-1297`). `AGENTS.md:9-13` explicitly forbids defaulted policy. The permission guard has also grown a meaningful fail-closed grammar and live repository checks (`home/common/claude-code/default.nix:817-900`).

### What does not work reliably

Package-limit stops recur in the sampled retained ledgers, including changes whose recorded verification was otherwise clean. In nix-config, [#115](https://github.com/fagenorn/nix-config/issues/115), [#121](https://github.com/fagenorn/nix-config/issues/121), and [#122](https://github.com/fagenorn/nix-config/issues/122) all hit package-size limits before eventual recovery or retention. The retained #121 aggregate was 589,625 bytes against a 524,288-byte cap. The ledger shows the same pattern in Nodo [#1460](https://github.com/elevenyellow/nodocom/issues/1460), [#1519](https://github.com/elevenyellow/nodocom/issues/1519), [#1295](https://github.com/elevenyellow/nodocom/issues/1295), [#1312](https://github.com/elevenyellow/nodocom/issues/1312), [#1293](https://github.com/elevenyellow/nodocom/issues/1293), [#1318](https://github.com/elevenyellow/nodocom/issues/1318), and [#1216](https://github.com/elevenyellow/nodocom/issues/1216). These purposive examples do not estimate a fleet failure rate. They support slicing work and packaging evidence incrementally so a clean implementation does not require a fresh implementation attempt solely because a whole-branch artifact is too large.

Attempt identity is too rigid where continuity matters and too weak where terminal truth matters. Argus issues 78, 79, 100, and 101, and Nodo [#1323](https://github.com/elevenyellow/nodocom/issues/1323), stopped because a new attempt could not adopt a preserved worktree even when the existing branch was the only useful lineage. Conversely, Nodo [#1314](https://github.com/elevenyellow/nodocom/issues/1314) was recorded `stopped` after the implementation had already shipped and was only reconciled when a person asked; Arcwave [#113](https://github.com/fagenorn/arcwave/issues/113) was closed in the ledger before its associated PR [#116](https://github.com/fagenorn/arcwave/pull/116) merged, and the user corrected it. A terminal receipt therefore needs separate, observed postconditions for implementation delivered, PR merged, and tracker closed.

The host capability model is inaccurate. `CLAUDE.md:62` says `orchestrate-issues` is Claude-only and Codex lacks the required host features, yet the September Arcwave Codex session emulated orchestration. That run exposed the real constraint: two owners contended for one worker slot while the parent repeatedly polled. The open core/profile issues do not currently specify host capability discovery, admission, or scheduling.

Fleet adoption has not begun on main. A current `resolve-project resolve --repo-root` check returned `not_onboarded` for `/Users/anis/Projects/arcwave`, `/Users/anis/Projects/nodocom`, and `/Users/anis/Projects/argus`. The guard still carries repository policy literals, including `elevenyellow/nodocom=dev` and `fagenorn/arcwave=dev` (`home/common/claude-code/default.nix:35-67`). Conformance has 17 registered checks (`home/common/agent-skills/scripts/conformance-registry.py:290-370`), but the three release-profile checks are explicitly `not_run` because there is no compiler (`home/common/agent-skills/scripts/conformance-checks.py:681-737`).

### Where tokens and turns are wasted

The clearest waste is scheduler churn. In Arcwave session `01a0a571-001a-7113-957c-86a61ee27bfd`, the root made 215 spawn attempts, 269 follow-ups, and 976 `wait_agent` calls, with only four compactions. Across 261.29 million tokens attributed to unique completions, 99.22% of input was cache-read. Responses that issued `wait_agent` accounted for 41.73% of sampled request-token volume; including exec-based waits raised that to 50.85%. These percentages cover only modern records in that one session with `token_usage_record`; legacy Codex records omit it, so this is neither a fleet estimate nor a whole-month cost share. Cache hits reduce recomputation cost, but they do not make 976 polling decisions useful. This is evidence for event-driven wakeups, explicit worker-slot availability, and admission control, not a reason to widen the release adapter.

Large entry prompts and repeated prose amplify that churn. Current shared skill sizes include `from-issue` at about 4,300 words, `sdd` at 2,519, `ship-issue` at 3,572, and `ship-release` at 4,432. The model matrix has explicit dispatch-site effort validation (`home/common/agent-skills/scripts/agent-model-matrix.py:147-184`), while the cost reporter now emits per-run models, efforts, phases, skills, agents, and statuses (`scripts/agent-costs.py:794-911`, `:1011-1080`). What is missing is a versioned observed-versus-declared report that can distinguish model/effort drift from scheduling waste.
