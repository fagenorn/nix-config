# Claude Code module

## Settings

The `env` of the generated `~/.claude/settings.json` sets `BASH_MAX_TIMEOUT_MS` to `3600000` (60 minutes), the ceiling for an explicit Bash timeout, so an agent can run `just build` or `just agent-workflow-tests` in the foreground under a timeout above its duration (#261); `BASH_DEFAULT_TIMEOUT_MS` is left unset, so a command with no explicit timeout keeps the host's 120 s default.

## Allow surface and lifecycle guard

Use `just show-claude-settings` to build and print the settings JSON (failing unless discovery finds exactly one artifact); its 22-entry allow surface allows the two lifecycle helpers `workflow-state` and `artifact-budget` outright, bare and as `~/.agents/bin/…`, and hands four lifecycle verbs, and the raise-label rule below, to a fail-closed `PreToolUse` hook. That hook's Python is `home/common/claude-code/lifecycle_guard.py`, a standard-library-only file that imports nothing from `agent_tools`: the registered command is a store wrapper that clears `NIX_PYTHON*` and runs it under `python3 -I` with `--policy` naming a store JSON file of the Nix-owned values (`authorizedOwners`, `integrationBases` and the `git`/`gh`/`jq` paths), so an owner change never touches the source, `just build` fails when the source or policy cannot load, and an unreadable or malformed policy blocks every Bash call. The hook splits the command into shell segments, tokenises each one, and adjudicates a verb **wherever a simple command starts** — after `(`/`{`/`` ` ``/`$(`/a `case` arm, after `!`/`time`/`then`/`do`, and behind `command`/`env`/`sudo`-style wrappers — comparing *token values*, so `git  push`, `git<TAB>push` and `"git" push` all count. A mention that is one quoted token (`echo "gh pr merge …"`), a heredoc body, or a comment is not a command and never triggers it. Everything the tokeniser cannot vouch for is refused rather than waved through: an unparseable command, shell source handed to `eval`/`sh -c`, and a guarded verb sitting in a non-command position (an argument to `xargs`, `timeout`, …) all block. Bare `Agent` remains inert under `defaultMode = "auto"`; verify the built artifact and guard with `tests/test_claude_permission_guard.py`.

## Detaching words

Before any of that, and before its policy loads, the hook refuses the detaching words `nohup`, `setsid` and `disown` in every repository (#278): wherever a simple command starts (bare, by path, after a redirection or with one attached as in `nohup>log`, or behind a wrapper and its option arguments — `nohup` is no longer a wrapper), anywhere in evaluator source, `env -S` command text or an unparseable command, and inside a quoted `$(…)` or backtick substitution, naming the Bash tool's `run_in_background: true` and `launch-scope exec` as the routes; a mention, a heredoc body, a comment and a trailing `&` pass, and a word handed to an argv runner such as `xargs` or `timeout` is an accepted residual.

## Adjudicated verbs

The verbs it does adjudicate are validated against the live repository: `git push` only as `git push [-u] origin <branch>` onto a non-default branch with no force/delete/tag/mirror flags, no refspecs and no namespaced refs (`refs/heads/main` and `heads/main` name the default branch too), `gh pr create` only as the exact `--repo/--base/--head/--title/--body` form whose repo is the detected slug and whose base is `origin/HEAD`'s branch, `git branch -d <branch>` (guarded globally, in every repo), and `gh pr merge` as the generalized `--repo <detected slug> --merge [--subject "..."] --delete-branch` form (or, in a repository with a declared integration branch, the release arm without `--delete-branch`: only the integration branch merged into the default branch, gated on a fully green check rollup instead of forge protection), optionally behind the exact literal prefix `unset GITHUB_TOKEN && ` derived from `bindings.tracker.credential_env.unset_before_invocation`'s exhaustive credential-name list (the remainder is still judged as the whole command, so nothing else can chain); the three repository-bound verbs additionally require the origin owner to belong to the guard's `authorizedOwners` set in `home/common/claude-code/default.nix` (the authoritative roster), and merging further requires an open PR based on the default branch (or the repository's declared integration branch, e.g. `dev` for `elevenyellow/nodocom`); a default-branch base additionally demands live protection with at least one required status check and admin enforcement on the feature arm, while a declared integration base is deliberately exempt from the protection demand — it is the development-pace branch, and its CI gate stays in the shipping flow's wait-for-checks. The merge's own `gh` lookups run with `GITHUB_TOKEN`/`GH_TOKEN` scrubbed from their environment, so they authenticate via the gh keyring credential (whose reach covers every authorized owner) rather than the narrower fine-grained PAT the shell exports; a machine with no keyring auth fails closed at the lookup. There is no defer path: once the hook adjudicates a verb it is validated-and-allowed or blocked, never handed back to the allowlist unexamined, and every uncertainty (unknown repo, unresolvable default branch, child timeout, non-zero or unparseable output) blocks. The guarantee is only as wide as that segment tokeniser — it approximates bash rather than being bash — which is why it refuses whatever it cannot parse, and why `tests/test_claude_permission_guard.py` carries an adversarial table (one case per class of "the parser and the shell might disagree") that any change to the guard must keep green.

## The raise label

The hook also refuses an agent adding the `instruction-budget-raise` label (#294): in a command that mentions that label, case-insensitively, a `gh` invocation in any position whose `--add-label` value contains it is blocked, in every repository and before any other verb is judged, and an unparseable command, `eval`/`sh -c` source or a quoted `$(…)`/backtick substitution that mentions the label blocks too, while other labels, `--remove-label` and quoted mentions pass. This catches mistakes and is not enforcement: Codex has no hook, and `gh api`, GraphQL and `curl` are outside the guard, so the protection that holds is the required `Instruction Budget` check plus the user seeing the label on the PR (`.agents/knowledge/rejections/ungated-agent-merges.md`).

## Plugins

`codex-plugin-cc` is the one plugin built from a pinned input plus a repo-owned patch (`patches/agent-plugins/codex-plugin-cc.patch`, the only patch in that directory); `lib/agent-plugins.nix` patches it into a store path and names its marketplace `nix-codex`. Claude enables two plugins from marketplaces of two different source types — `skill-creator@claude-plugins-official` from a `github` marketplace and `codex@nix-codex` from a `directory` marketplace pointed at that store path. Codex has no Nix-declared marketplace: its marketplaces and plugins are runtime-managed inside `~/.codex/config.toml`, which Nix does not own.

## Editing the codex-plugin-cc patch

To edit `patches/agent-plugins/codex-plugin-cc.patch`: work in a scratch clone of the pinned upstream rev (see `flake.nix`), apply with `git apply --unidiff-zero` (the patch is zero-context; plain `git apply` rejects it), regenerate with `git diff -U0 <pin>`, and bump `patchRevision` in `lib/agent-plugins.nix`. Run the plugin's suite as `env -u CLAUDE_PLUGIN_DATA -u CODEX_COMPANION_SESSION_ID -u CODEX_COMPANION_TRANSCRIPT_PATH node --test tests/*.test.mjs` — with the live Claude-session env unscrubbed, 4 upstream tests fail spuriously. The six test files that write under the shared state root (`runtime`, `state`, `liveness`, `reviewer-detach`, `broker-reaping`, `worker-postmortem`) call `pinHermeticStateRoot` (`tests/helpers.mjs`), which pins `CLAUDE_PLUGIN_DATA` to a private temp root and group-kills every broker recorded there at file teardown; `isolation.test.mjs` pins and restores a root of its own per test and is left alone. That, plus a `teardownBrokerSession` that kills by default and a broker that exits on its own once nothing wants it, is why a run deposits no `codex-plugin-test-*` state dirs in `~/.claude/plugins/data/codex-nix-codex/state/` and leaves no surviving `app-server-broker` or `codex app-server` processes. When two branches both edit this patch, reconcile it by applying each side to a scratch clone and three-way merging the *source trees*, then regenerating — never by merging the patch text: `patch -p1` applies a textually-merged zero-context patch at lenient offsets with no error, so a wrong merge is silent, and an identical `patchRevision` bump on both sides hides the collision from git's conflict list entirely. To assert anything *about* the patched plugin source (a plan's verification gate, a spot check), read the scratch clone or the built store path — never `grep` the patch text: a zero-context patch carries no file attribution per line, so a patch-wide `grep -c` counts hunk lines from every touched file at once and cannot tell you which file a match sits in.
