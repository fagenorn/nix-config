# ADR-guard-009 — Production rules live in the contract and the guard refuses them in every mode

Context: a manager in `auto` was refused harmless work, and running managers in `bypassPermissions` needs something that still stops what must never run. Decision: production rules are declared in the project contract (ADR-project-contract-007): changing commands, read-only routes, key file globs, MCP tools and a release profile; the guard copies them into the derived row and refuses in every permission mode a changing command in that project's checkout, a key file write there through Edit, Write, MultiEdit or NotebookEdit, and a declared MCP tool call anywhere; each refusal names the approved release path, or the console's Activate for the console activation rule (ADR-system-004); the rules are read without the row check, because a rule only refuses and confirming it would let an unreachable `origin` fail open; a manager runs in bypass only where the rules are in place or the project declares no production. Rejected: keeping the per-command judgement of `auto`, which stalled sprints on prompts nobody could answer, and naming binaries rather than contract command ids, which a script, alias or recipe hides.
