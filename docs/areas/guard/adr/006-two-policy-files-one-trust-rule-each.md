# ADR-guard-006 — The guard reads a trusted store base policy and an untrusted compiled policy

Context: the guard needs facts it trusts absolutely (owners, programs) and facts derived from the registry and contracts, and the compiled policy is written at activation, so it is a user-writable file. Decision: two files with disjoint closed schemas, the store base policy holding every trusted member and the compiled policy only derived rows and their derivation; no trusted member is taken from the compiled policy, and a row is a claim confirmed before use (ADR-guard-007) except its production rules, which only refuse and are read unconfirmed (ADR-guard-009); a bad compiled policy contributes no row, a bad base policy blocks every Bash call. The guard is not a sandbox: it catches a cooperating session's mistakes, and branch protection, the required checks and the owner are what hold. Rejected: one policy file carrying owners and rows, which a session could rewrite to authorize itself.
