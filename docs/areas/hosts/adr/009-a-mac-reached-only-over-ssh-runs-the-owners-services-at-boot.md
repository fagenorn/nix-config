# ADR-hosts-009 — A Mac reached only over SSH runs the owner's services at boot

A launchd user agent loads in the owner's `gui/<uid>` domain, which exists only while the owner is logged in at the screen, and eleven-m5 is reached only over SSH with nobody logged in there as the owner, so its login agents (the console, verify-pending, the secrets decryption and the cache proxy) never loaded (#1290). A host that sets `ownerServices.atBoot` runs those four as launchd daemons in the system domain, each as the owner through `UserName` with the owner's `HOME`, built from the definitions of their login agents, which are disabled there; the activation boots each legacy login agent out and deletes its plist before any daemon loads, and stops when one will not boot out, so that no daemon starts beside a loaded copy. mbp keeps its login agents. A daemon of the owner answers on loopback as the login agent did, so another account on the shared Mac reaches its port, the boundary ADR-console-008 accepts. The rejected alternative is turning automatic login on so that the login agents load, because that session would sit unlocked at the screen of a Mac another person uses.
