# ADR-hosts-008 — `claude` starts under the console's profile choice, not the project's binding

`claude-account run` started every session of a project under the account the project was bound to in `bindings.tsv`, whatever that account's allowance, and the owner switched by hand; #839 decided that a new session starts on the profile with the most room, which only the console knows (ADR-console-023). With `CLAUDE_ACCOUNT` unset and no configuration directory of the caller's own, the launcher starts under the console's answer on `GET /api/profile`, asked under a one-second deadline, and only when the console does not answer falls back to its own guess: the first line of `chosen-profile`, then the most recently used signed-in named profile, then the first by name, the last two skipping a profile the owner excluded (#842, #1028). Only a named profile is an account (#1016): the client starts unprofiled only when none exists or every one is excluded, and a launch that names an answer file starts no client when every account is out (ADR-system-006). `CLAUDE_ACCOUNT=<profile>` still overrides one launch. The rejected alternative is the project's binding read at launch, which pins a project to one account however little of its allowance is left; a console that is down costs a launch at most one second.
