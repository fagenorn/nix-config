# ADR-hosts-006 — The Codex plugin is a pinned upstream plus one repo-owned zero-context patch

`codex-plugin-cc` is the reviewer path to Codex, the repository needs behaviour the upstream lacks (a reviewer that refuses a stdin or stdout another live reviewer holds, #693; a `task --json` payload that says why a review failed, #790), and the plugin is installed from a store path, so every change must be reproducible from the flake. The plugin comes from a pinned flake input, and one patch, `patches/agent-plugins/codex-plugin-cc.patch`, is applied to a copy of it in the store path that serves as the `nix-codex` marketplace. The patch is zero-context: it is edited in a scratch clone with `git apply --unidiff-zero`, two branches' edits are reconciled by merging the patched source trees and regenerating it, never by merging its text, and every change bumps `patchRevision` in `lib/agent-plugins.nix`. A flake update can make the patch stop applying, and the build then fails until it is regenerated against the new pin. The rejected alternative is a fork of the upstream as the input, which spreads the delta over the fork's history and needs a rebase at every update, where one patch keeps the whole delta in one reviewed file of this repository.
