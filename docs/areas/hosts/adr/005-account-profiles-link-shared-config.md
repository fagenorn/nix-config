# ADR-hosts-005 — Account profiles share configuration by links to `~/.claude/<entry>`

Several Claude accounts run side by side on one host, each with its own login, and Claude Code reads one configuration directory, `CLAUDE_CONFIG_DIR`, so each account needs a directory of its own while settings, `CLAUDE.md`, skills, agents, plugins and transcripts stay those of the Nix-generated `~/.claude`, which changes with every generation (#373). A profile directory under `~/.claude-accounts/profiles/` is the account's `CLAUDE_CONFIG_DIR`, and its shared entries are links to the `~/.claude/<entry>` paths, never to their store targets, so one switch reaches every profile and a conversation carries over when a session changes account. `~/.claude.json` is the exception: it holds the login, so a new profile gets a one-time copy without it, and an MCP server merged into `~/.claude.json` later reaches an existing profile only once it is merged into that profile's copy too. The profiles are runtime-owned; Nix owns only the code that creates and uses them. The rejected alternative is a copy of the shared configuration in each profile, or links to the store targets, because either goes stale at the next generation and needs a step per account after every switch.
