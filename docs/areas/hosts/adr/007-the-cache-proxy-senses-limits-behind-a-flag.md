# ADR-hosts-007 — The cache proxy senses limits behind an off-by-default flag

The console's capacity strip needs each account's remaining share and next reset, and the cache proxy already sees every response of every session on the host, whose unified rate-limit headers say where each account stands (#849, #860). The proxy sits on the path of every request, so a fault in it costs more than a feature in it earns: its forwarding stays byte for byte unchanged, and every behaviour beyond forwarding is a flag that is off by default, with no object for it while the flag is off. With `--sense-limits`, which only the host configuration passes, the proxy reads those headers and each request's account and session and posts the reading to the console's loopback `POST /api/readings`; nothing is added, retried or held for the reading, a console that is down costs a request nothing, and no header value, sign-in or device id is logged, reported or stored. The rejected alternative is a separate usage endpoint or status-line feed: a second route to what the proxy already holds, and one that would have the console read a credential.
