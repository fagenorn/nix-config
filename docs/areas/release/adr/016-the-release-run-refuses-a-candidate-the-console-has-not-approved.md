# ADR-release-016 — The release run refuses a candidate the console has not approved

`release transaction run` published whatever candidate its caller named once the preview's tokens were supplied; a token proves the caller previewed the plan, not that the owner wanted that commit at that version, and removing the release from the manager permit (ADR-console-094) left the command unguarded. So every `run` that goes on to write (a new candidate, a resume, the bare rerun of a finished release's sync) asks `approvals(commit, version)` after the confirmation checks and before the router, land lock and store, and refuses `release_unapproved` unless an approved release card of the console (ADR-console-097) records exactly that pair. It fails closed as `approval_unreadable`, reads the host console's store at `release_card.host_store()`, never `$HOME`, gates nothing else, and every parser sets `allow_abbrev=False`. Rejected: a chat yes, a stored authority class or the manager permit as the approval, none of which the command can trust.
