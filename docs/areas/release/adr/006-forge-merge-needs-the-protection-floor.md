# ADR-release-006 — The forge merge runs only above the protection floor

A forge merge of the integration branch into the default branch can be defeated by a missing protection rule, head-branch auto-deletion, a moved pull request or an advanced base, and the provider answers a failed merge ambiguously. So `pr_merge` first reads strict protection with required contexts and enforced admins, `delete_branch_on_merge` off, an open pull request at the candidate commit and a base tip equal to `merge.base_tip` (a miss is `rejected` with `precondition_failed`), makes one mutation, `gh pr merge --merge --match-head-commit <commit>` with never `--admin`, `--auto`, `--delete-branch`, `--squash` or `--rebase`, and is `satisfied` only when the merge commit's parents are exactly `[merge.base_tip, candidate.commit]`. Rejected: merging on green checks alone and trusting the provider's merge answer.
