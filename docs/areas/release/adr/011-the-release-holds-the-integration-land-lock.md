# ADR-release-011 — A two-branch release holds the integration land lock until it has merged

A release pull request's head is the integration branch, so every landing there moves the head and restarts its required checks, and the cycle is lost while the caller waits for the preview to become runnable, before `run` exists. A profile with a post-release sync (ADR-release-010) therefore holds the integration branch's land lock (ADR-claims-009) from before the first preview until it has merged. The caller (the ship-release skill) acquires it with a wait and releases it on every stop short of a run except the confirmation stop and `release_busy`; the preview takes it one-shot when free (ADR-release-008); `run` proceeds only on a one-shot `already_held` check, keeps the lock across the confirmation stop, and releases it at the candidate commit on `done`, `attention` and `abandon`, before the sync. No clock is added: a release that dies holding the lock falls to the land lock's own staleness rules. Rejected: a hold taken inside `run`, which starts after the lost cycle, and dropping the lock at the confirmation stop, which lets a landing move the head and forfeit the green run.
