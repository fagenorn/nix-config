# ADR-release-015 — A guard-refused merge runs again on a later run

A guard refusal is an invoke `rejected` with class `authorization_denied`, raised before the one mutation, so it applied nothing, yet the core parked it as not retryable for good, and a merge the guard refused once could only be abandoned and created again. So the `created` event may carry `rerun_denied`, the sorted distinct action names whose guard-refused attempt may run again, which the release driver fills with the merge action only for a profile with a sync: a named action's predecessor rejected `authorization_denied` passes `not_retryable` and `window_closed` outside `recovering`, while `inspection_required`, `not_absent` and `budget_exhausted` still apply, so it runs at most `MAX_ATTEMPTS` times. Replay enforces the same rule, and a stored transaction adopts the member on resume (`TransactionStore.adopt_rerun_denied`). Rejected: abandoning and re-creating the release after every guard refusal, and making `authorization_denied` retry-safe for every action, which would re-run a refused tag or release.
