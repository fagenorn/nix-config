# ADR-release-005 — An adapter answers accepted, rejected or unknown, never succeeded

An adapter's mutating call can time out, lose its response or fail after the provider applied it. So `invoke` returns only `accepted`, `rejected` or `unknown`, with no `succeeded`: only the core's later `inspect` says an effect landed, a timeout or unexplained failure after a mutation is `unknown`, no adapter retries a mutation, and `release_adapter.core_binding` adds no retry or ordering policy. Every adapter therefore needs a faithful `inspect` for each operation it mutates with. Rejected: an adapter that reports success from its own call, which lets the core record an effect that never landed or retry one that did.
