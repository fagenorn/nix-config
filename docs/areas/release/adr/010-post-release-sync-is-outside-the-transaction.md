# ADR-release-010 — The post-release sync runs outside the transaction and never merges

A two-branch release leaves the default branch one merge commit ahead of the integration branch, and the next release refuses `release_pr_behind` until it is back; a fast-forward push is refused where a pull-request-only check is required, and the guard admits no refspec push. So the sync is two forge requests, `sync_branch` and `sync_pr`, that no profile node can bind: the driver derives it and runs it once every publication action is satisfied, pushing a disposable `sync-<default>-into-<integration>-after-<version>` branch at the release merge commit and opening one pull request from it, in a spelling the guard admits for any agent (ADR-guard-008). Nothing is stored, a failed sync changes no state, action, token or receipt of the release, and the core never merges the sync pull request. Rejected: modelling the sync as profile actions, which would let a failed sync park a published release and change the forge descriptor digest that pins every profile and token.
