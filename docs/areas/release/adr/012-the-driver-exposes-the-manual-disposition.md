# ADR-release-012 — The driver exposes the manual disposition and leaves roll-forward out

A release parked after an effect whose deploy can never go green blocked its target for ever: resume needs the old commit deployed, `abandon` is refused once an action had an effect, a new candidate is refused `release_in_flight`, and the driver, the core's only caller (ADR-release-002), called no disposition. So the driver exposes one, ground `no_recovery_path`, as `preview --dispose no_recovery_path --reference <why>` and `run` with the same arguments and `--confirm <token>`, for the current release parked `attention_required` with an effect: `run` re-derives the plan (ADR-release-008), inspects every action again under held custody, refuses `recovered` when all read `satisfied`, and issues one human grant at authority class `release`. The terminal is `failed`, never `succeeded`, the reference is sealed in the receipt and the version stays reserved. Rejected: exposing `roll_forward` and the `successor_succeeded` ground, which need a second creation path and a parent parked until its child seals, while disposing then releasing reaches the same end.
