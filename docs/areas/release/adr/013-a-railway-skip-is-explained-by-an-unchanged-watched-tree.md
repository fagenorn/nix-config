# ADR-release-013 — A Railway skip is also explained by an unchanged watched tree

The `railway-deploy` watch accepted a `SKIPPED` deployment only on CI evidence, so a release whose merge left one service's directory untouched parked `skip_unexplained` although that service was skipped correctly and still served the right content; check runs say why Railway may have skipped, not what the service serves. So a skip the CI route cannot explain is `satisfied` when Railway states `No changes to watched files`, the first older non-skipped row serves on the target branch with the same root directory, the watch patterns are absent or exactly `["**"]`, and GitHub's compare shows that row's commit an ancestor of the released commit with fewer than 300 files, none under the root directory or equal to the config file (ADR-release-007 for the watch itself). Rejected: Railway's `skippedReason` alone, the commit status Railway posts (green for a skip), and the previous succeeded release's deployment.
