# ADR-claims-001 — Issue comments called markers hold every claim fact; labels only filter

Several sessions on several hosts may try to deliver one forge issue at once, so each claim fact needs a record that the forge orders and that a late write cannot undo. Every claim fact therefore lives in an issue comment called a marker, and a label such as `in-progress` or `owner-action` is only a filter over the markers, which each verb repairs from them. Among the live markers of one kind the smallest comment id wins, because the forge assigns ids in creation order, and a marker is ended only by posting an `end` marker that nothing edits or deletes, so a delayed edit can never revive a released claim. The rejected alternative was labels as the state: they are easy to read, but a label is one bit that anyone can add or remove at any time and the forge offers no compare-and-set on it, so two writers could both believe they won. The cost is that the contest assumes a listing shows every comment created before it started, and that `end` markers accumulate on the issue for good.
