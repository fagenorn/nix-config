# ADR-claims-004 — Landings serialise on a compare-and-swap ref

Two deliveries to one integration branch must not merge at once, and they run on different hosts, so no local lock serves. The lock is the ref `refs/agent-locks/land/<branch>`, whose value is the holder's pull-request head: it is created by REST, and moved and deleted only through the GraphQL `updateRefs` mutation with `beforeOid`, a true compare-and-swap whose failure is classified by reading the ref again, never trusted. The holder is derived from the open pull request headed at the lock, never stored. The rejected alternatives were a lock local to one host, which no other host can see, and the REST ref deletion, which is unconditional and cannot tell the holder's lock from a successor's. The cost is one more read after every swap, and a holder merges only on `already_held` or `moved`, because `acquired` also exits 0 and means the lock was lost and taken again.
