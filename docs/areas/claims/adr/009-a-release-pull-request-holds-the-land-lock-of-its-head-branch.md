# ADR-claims-009 — A release pull request holds the land lock of its head branch

A release pull request merges the integration branch into the default branch, so its head is the integration branch itself, and every landing moves that head and restarts its checks. `forge-claim land acquire --release` therefore lets a same-repository pull request headed by the locked branch and based on the default branch hold that branch's land lock at its head, and every caller derives such a pull request as the holder with no flag. A new release's wait passes `--follow-head` and takes the lock at whatever head its pull request has reached; when its own old lock sits at the sha it started from, the wait deletes that lock and acquires again, answering `acquired`, never `moved`, so the release writes its notes and version again at the new head (issue 901). The rejected alternative was to let a release move its lock to the new head as a lander does: `moved` tells a holder it kept the lock without a gap and may merge without a resync, which is false for a release whose branch advanced under it. The cost is that a waiting lander can take the lock in that gap and the release then waits behind it; what the release driver must do is ADR-release-011.
