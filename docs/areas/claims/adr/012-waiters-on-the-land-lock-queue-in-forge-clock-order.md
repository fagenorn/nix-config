# ADR-claims-012 — Waiters on the land lock queue in forge-clock order

`forge-claim land acquire --wait` once polled with nothing ordering the waiters, so a released lock went to whichever polled first, and one wait lost two free windows to later arrivals. Each waiter now registers a ref `refs/agent-locks/land-wait/<branch>/<since>-<pr>-<beat>`, both times read from the forge's `Date` header and never from a host clock, and the waiter with the smallest live `<since>` is first: a live open pull request ahead of a waiter keeps it from creating a free lock or taking a closed one over, until a short grace of its own bounds what a dead first waiter costs. The queue decides only who tries: the lock is still granted only by the create and the compare-and-swap of ADR-claims-004, and any failed queue read or write makes that poll attempt unordered instead of failing the wait. The rejected alternative was a queue that grants the lock, where a forged, stale or unreadable registration could make two holders or none; here the worst a registration can do is delay a waiter. The cost is about nine forge calls a minute for the first in line, and strict order only once every host runs the new client.
