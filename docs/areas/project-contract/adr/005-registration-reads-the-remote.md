# ADR-project-contract-005 — `adopt-project verify --register` reads one pinned commit of the remote

Registering a project in the fleet registry vouches that its adoption is integrated, and a checkout can sit on any branch with any uncommitted state, so reading it would register something the remote never held. `--register` therefore lists `origin`, pins one commit of the remote's default branch, exports it and runs every check there, reading nothing from the checkout. The contract on the default branch stays the authority when it resolves: registration follows the integration branch it names, pinned and checked the same way, and a conflicting `--integration-branch` operand refuses; the operand names the branch to read only when that contract does not resolve. Rejected: reading the checkout, which needs no fetch and works offline but lets a local branch or an uncommitted edit stand in for what was merged.
