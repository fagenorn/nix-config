# ADR-project-contract-023 — Node programs are judged by node --check and ESLint through one adapter

The never-rise check (ADR-project-contract-017) held no enforcer for a Workflow program, so a syntax error or an unused binding in one passed it, and ESLint alone cannot read a program that opens with an `export` and uses a top-level `return`. The adapter `node-lint` therefore judges each program as the runtime loads it: the first `export const meta` becomes `const meta` and the text is the body of an anonymous async function of the runtime's names, so every line keeps its number. A tracked `.js` file with a line starting `export const meta`, at either revision compared, is a program, so a branch that breaks that line is still judged. `node --check` and ESLint's recommended set, mapped to NODE11 to NODE14, are count rules, and a suppression naming no rule or no reason is NODE15, so the programs stay unedited and the base carries their existing findings. The pinned Node and ESLint sit in the platform tools directory beside Ruff and run by command name on that directory alone (ADR-project-contract-020), and an unusable tool or output fails closed as `enforcer_failed`. Rejected: an ESLint configuration in the repository, which would change the programs' tree, and a record of store paths, which rule P3 forbids.
