# ADR-project-contract-007 — A contract declares its production rules, or that it has none

No fixed rule can refuse a change to a project's production without a declaration of what that production is, and the guard and the console read that declaration from the snapshot, never from the contract file. The contract gains one optional top-level member, `production`: `{"none": true}` declares no production and admits no rule beside it, while `{"none": false, ...}` declares the commands, key files and MCP tools that change production, the routes that only read it, the release profile through which a change is allowed and, optionally, the changing command the console's Activate runs (ADR-system-004). `none` is always required, so a project that has not answered, `not_declared` in the snapshot, is told apart from one that declared none. A host whose installed resolver predates the section refuses a contract that carries it until that host switches, a cost accepted for every new member. Rejected: reading an absent section as no production, which would let a project that never answered run its production commands with nothing to refuse them.
