# ADR-system-007 — agent_tools moves to .NET under one reference graph

This supersedes ADR-system-002, ADR-system-003 and ADR-system-005: `agent_tools` moves to .NET area by area (#1817). One platform package ships Python commands, a Native AOT guard binary for start-up and one JIT tool with subcommands. Each area is a project under `dotnet/` with its tests, in seven layers: System (only the `gh` forge transport), ProjectContract, Claims and Guard, Release and Verification, Delivery, Console, then Hosts, the composition root with the command table. A project references only lower layers, never Delivery to Release or Guard nor Console to Guard: 31 edges, held by `DisableTransitiveProjectReferences` and an architecture test that also refuses a self `Process.Start`. [The architecture guide](../../../guides/architecture.md) tables them and each shared format's sole owner and writer. A command's runtime flips with its `lib/agent-tools.nix` row in its own slice, which proves its rollback, the previous host generation, reads what it wrote. State keeps its paths and formats; SQLite uses Microsoft.Data.Sqlite, no EF Core. Python calls a moved area via a logic-free JSON adapter deleted with its last caller, and keeps `forge_api` till its last caller moves. A parallel required check runs the build and `dotnet test`, its warm median enforced under 4 min. Rejected: Python's `gh` calls via the .NET tool (a process start each), and System as a drawer for code no area owns.
