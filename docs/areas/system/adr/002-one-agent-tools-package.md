# ADR-system-002 — Agent-workflow Python is one standard-library package with one install route

The agent-workflow helpers were some two dozen loose Python files that Nix linked one by one into `~/.agents/bin`; not being a package, they could not import each other, so each spec invented its own loader and copied knowledge between modules. Every helper is a module of the one standard-library package `agent_tools` under `python/`, and a command is that module plus exactly one row of the command table in `lib/agent-tools.nix`, its only install route: the row becomes a launcher of the platform package (ADR-system-005) that runs `python3 -I -m agent_tools.<area>.<module>` from one Nix-built environment, so nothing on `PYTHONPATH` or in the working directory shadows the store copy. The price is that a module needing a third-party dependency cannot join the package without revisiting this record. Rejected: keeping the loose files with a loader per spec, which is what failed; wrapping each command with `buildPythonApplication` or a flat directory on `PYTHONPATH`, either of which lets a caller's `PYTHONPATH` shadow the store copy; and adopting a third-party dependency such as `jsonschema` now, which would change the commands' error text and exit behaviour. Superseded by ADR-system-007, under which these rules bind only the Python commands while their areas move to .NET.
