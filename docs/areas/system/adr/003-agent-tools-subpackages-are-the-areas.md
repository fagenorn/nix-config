# ADR-system-003 — agent_tools subpackages are the docs areas, and cross-area imports follow one table

`agent_tools` was one flat package of over a hundred modules, so an area showed only through file-name prefixes and any module could import any other. Each docs area is a subpackage of `agent_tools`, one level deep and named by its area with hyphens as underscores; code no area owns lives in `agent_tools.system`; the top level keeps only the Instruction Budget gate closure; and a module imports another area's module only through an edge listed in the one reviewed table of the layout test. The rules are P9 to P13 of `docs/standards/package-layout.md`. A record that names a flat `agent_tools.<module>` means the module now at `agent_tools.<area>.<module>`, its area the `docs/CONTEXT-MAP.md` row that governs it. Rejected: keeping the flat package with areas shown by file-name prefixes, which leaves every import legal and no boundary a test can hold. Superseded by ADR-system-007, under which each area becomes a .NET project and this table binds only the Python subpackages until they move.
