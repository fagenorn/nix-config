# ADR-system-004 — Host activation runs only through the console's Activate

The activation line told the owner to run `just switch` in a checkout, so a merged change was activated in a terminal outside the console, and the guard's one approved path for a production command, the release profile, has no activation step: a host activation is not a release. A contract's production section may name one of its changing commands as its console activation (`production.console_activation`); the guard refuses that command in every agent session with a sentence naming the console's Activate, and the console's own service runs it from the activation line (ADR-console-073) for the commit the line shows. The run builds that commit in a clone of the console's own, never in the checkout, runs in its own scope so that it outlives the console's restart, holds one claim until its whole process tree is gone, and succeeds only when its recorded exit is 0 and the host's configuration revision is the commit. Rejected: activating through the release profile, which is a release path; building in the checkout or a `git worktree` of it, which writes to the owner's checkout; and judging success by the configuration revision alone, which reaches the commit before a failing switch ends.
