# ADR-verification-008 — Macs run verification only while a user is logged in

A darwin verification job needs `gh` credentials, which this setup keeps in the login keychain, and a launchd job that can read them runs in the user's `gui/<uid>` domain, which exists only while someone is logged in at the console (issues 668 and 705). On a login host (mbp) the job is a launchd user agent in `gui/<uid>`, with no LaunchDaemon form and no credential outside the keychain: with nobody logged in the agent never loads and no pass runs, the kick still writes the switch request, prints one `verify-pending-kick:` notice and exits 0, the user-agent reload step skips with one log line, and a host-bound check there surfaces through the stale-check owner prompt (cause `silent`) that another host's pass posts after 7 days. A host with `ownerServices.atBoot` (eleven-m5) instead runs the job as a launchd daemon of the owner in the system domain from boot, its `gh` reading its own hosts file (ADR-hosts-009, #1290). The rejected alternative is a LaunchDaemon with a token file on a login host, because it would keep a credential outside the login keychain only so that a Mac someone logs in to could verify while logged out.
