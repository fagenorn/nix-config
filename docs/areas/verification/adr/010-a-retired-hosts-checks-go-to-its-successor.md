# ADR-verification-010 — A retired host's checks go to its successor or are reported

The drive of `anis-desktop` failed on 18 Nov and the host will not run passes again, yet held blocks name it, so a check bound to it would wait forever and every other host would post a stale prompt naming a host that cannot answer (#1291). The runner carries one map of retired hosts to successors, `verify_run.RETIRED_HOSTS` (`anis-desktop` to `eleven-m5`), the default of `pass_repo` and `pass_issue`, so every pass agrees without a new flag. A successor takes a retired host's check exactly when the unattended gate would run it (ADR-verification-003) and, being darwin, a script only when its text names nothing in `verify_run.LINUX_ONLY`; any other check is one `pending` line with reason `host_retired` on every host and is never answered, and a writing pass ends the retired host's live prompts and due markers with that reason, renaming in place an `ask` or `act` prompt another host can answer. The rejected alternative is a change to the block grammar and its lint that refuses the host, or an edit of every held block that names it, because the map is undone by deleting one entry while either alternative changes what every held block already says.
