# ADR-verification-004 — Only OWNER and MEMBER blocks and markers count

The repository may be public, so anyone can comment on a held issue, and a block or a marker is the only input the runner acts on; a marker also decides contests such as the `verify-run` lease and the `verify-closed` close (issue 630). Only a comment whose author association is `OWNER` or `MEMBER` carries a block or marker the runner reads, a contest re-read included: another author's block is never selected, and another author's marker neither wins nor ends a contest and is invisible rather than reported. A pass that writes first checks that its own `gh` account would be trusted, the owner of a user-owned repository or an active member of the owning organization, and any other account ends the project with one `runner_untrusted` line before any write or run, so a collaborator account cannot run a pass, as it would write markers it could not read back. The rejected alternative is trusting every author who can comment, a collaborator or a contributor included, because on a public repository that would let anyone hold, run or close a verification; the association is the one trust check, so the authority of the repository's owners and members is the boundary.
