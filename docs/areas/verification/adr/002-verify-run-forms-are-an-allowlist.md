# ADR-verification-002 — A verify block runs only a contract command, a committed script or a built-in probe

A verify block sits in a hold comment that a runner executes later, unattended, on a host, and the history study behind issue 625 found holds carrying code the runner should not trust. The run forms are a closed allowlist of three: `{"command"}` runs a command id declared in `bindings.commands` with its declared argv and nothing else, `{"script"}` runs a file committed with mode `100755` at an exact path of the repository, and `{"probe"}` runs a built-in read-only probe by name. Any other shape is refused `run_form`, inline code or an appended argument `inline_code`, and a reference the lint cannot confirm is refused, so a block trusts only installed or committed code, never code in the comment, and a check that needs another tool waits until it is committed as a script or becomes a probe. The rejected alternative is admitting general tools such as `git`, `python3`, `nix`, `gh` or `curl` behind a lint of their arguments, because the lint cannot tell their safe arguments from code-carrying ones: a declared argv is often a `just` recipe, which pastes its parameters into shell lines unquoted and runs a surplus argument as another recipe.
