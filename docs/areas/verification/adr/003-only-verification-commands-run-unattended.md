# ADR-verification-003 — Only workflow.verification commands with no effects run unattended

The runner executes held checks on every host with no person present, and a contract `command` can be any declared command, one that deploys, publishes or spends money included (issue 630). Unattended, the runner runs a check only when it is `kind: evidence` with no `ask` or `act` run, has `effects` of `none`, never `live` or `paid`, and, for a `command` run, names a command listed in `workflow.verification`; its output is trimmed and never trusted. A check that asks, acts or needs `live` or `paid` effects reaches the owner through an owner prompt whose approval lifts only the effects gate, while a `command` outside `workflow.verification` raises no prompt and is reported `command_not_verification`, even when it is read-only. The gate lives in `verify_exec`, apart from the lint, so a block the lint accepts can still be skipped at run time. The rejected alternative is running any declared contract command whose check asks for no effects, because a block's `effects` is the author's claim and a declared command can deploy, publish or spend money whatever the block says; `workflow.verification` is the one list the project itself declares as its verification.
