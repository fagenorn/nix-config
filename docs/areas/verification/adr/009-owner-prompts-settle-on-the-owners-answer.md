# ADR-verification-009 — An owner prompt settles only on the owner's recorded answer or a final state

Some held checks need a person: a question (`ask`), an action (`act`), approval of a live or paid command, a decision about a failed or expired check, or a look at a host that went silent (issue 631). Each prompt is an `owner-action` marker with check boxes, posted once per identity ever, ended prompts included, and a stale prompt's identity includes its host; only the owner's recorded answer or a final state settles a prompt, and its outcomes, `rejected` included, are fixed. An approve prompt is bound to its command by the `run` digest and consumed once, by the named host only, through a `verify-run consumed=<id>` marker; a changed command ends it `changed` and asks again, approval lifts only the effects gate, and `verify-pending approve --all-live` never ticks a `paid` prompt. A retired host's live prompts end `host_retired` without an answer (ADR-verification-010). The rejected alternatives are a prompt the runner settles itself, on a default or a timeout, because the runner would then decide for the owner, and a prompt posted again once it ended, because it would nag.
