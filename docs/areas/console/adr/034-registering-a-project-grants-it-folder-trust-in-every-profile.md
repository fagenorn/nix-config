# ADR-console-034 — Registering a project grants it folder trust in every profile

Context: `--bg` refuses an untrusted folder, and trust lives per profile in `.claude.json` (#1078, #1183); the client documents the key and the refusal at https://code.claude.com/docs/en/permissions#project-allow-rules-and-workspace-trust and https://code.claude.com/docs/en/errors#workspace-not-trusted-when-dispatching-a-background-session. Decision: the owner's Register approval writes the documented `hasTrustDialogAccepted` key in every profile. So do the start-up sweep of registered projects and the adding of a profile. The write uses an exchanging rename that merges again any document it displaced, then is read back and logged. Rejected: an undocumented route such as `CLAUDE_CODE_SANDBOXED`, and a plain-rename fallback that could overwrite a client's write unseen.
