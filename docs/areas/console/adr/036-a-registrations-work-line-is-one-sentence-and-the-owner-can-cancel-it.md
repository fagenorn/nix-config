# ADR-console-036 — A registration's Work line is one sentence, a failure's way out is an option, and the owner can cancel a registration

- **Status:** accepted
- **Decided in:** #1088

## Context

ADR-console-035 moved every registration failure onto a counted card and left the Work column with one line. The flow is live, and the next round of the owner's review found the rest. An adoption waiting for its pull request still drew change lines, a note, a link and a `Close` button under its line, although the card or the inbox already held all of it. A failed apply named a leftover copy and told the owner to ask an agent to remove it, because the adoption tool refuses a retained worktree and had no way to clear one (ADR-console-035 D7). A signing failure sent the owner to edit the repository by hand. A missing platform manifest told the owner to switch the computer's configuration without naming the one command that does it. A long path or project id broke in the middle of a word at 480 px. The owner also had no way to drop a registration: `Close` only hid the box until the next frame. The owner's rules stay binding (ADR-console-035 Context): everything that needs the owner is a counted card, the Work column holds only the one-line state, every failure says in plain words what to do next, and no command other than `just switch`, no plan id, hash or absolute path reaches the page.

## Decision

**D1. The Work line is one sentence.** A registration whose adoption waits reads `The pull request of <name> is not ready to merge yet.` and, once the pull request can be merged, `The pull request of <name> is ready to merge.`. With an adoption, the Work entry carries no change lines, no draft and no link: the ready card in the inbox keeps the one pull request link (ADR-console-030 D6). An adoption note that has no card of its own (a closed and set-aside pull request) joins the sentence after a space. This amends ADR-console-030 D9 and ADR-console-035 D3 and D5.

**D2. Close is removed.** The Work column no longer draws `Close`. It hid the panel until the next frame or reload while the cards stayed, which the owner took for a way to drop the registration. The only control left in the registration's Work box is `Cancel registration` (D7), when it is offered.

**D3. Every failure's next step is at most two sentences.** An apply or plan failure names its cause in one sentence and its way out in one, in the words of the option that is on its card. An uninstalled platform manifest reads `Run just switch on this computer to install them, then choose Try again.` for a plan (`MANIFEST_STEP`) and `Run just switch on this computer to install them, then choose Apply it again.` for an apply (`MANIFEST_NOTE`); `just switch` is the one command the page may name, and it is the owner's to run. A signing failure reads `Set up a signing key on this computer, then choose Apply it again.` (`SIGNING_NOTE`) and no longer asks the owner to edit the repository. This supersedes the manifest words of ADR-console-035 D8 and its signing advice.

**D4. A failed apply's kept copy is removed by the console, by the adoption tool's acknowledged cleanup.** The adoption tool refuses a retained worktree and deletes one only under an acknowledged cleanup (ADR-project-contract-004). The cleanup is the tool's own function, reached two ways: `adopt-project apply --discard-retained` (one child that removes the copy, then applies) and `adopt-project discard` (removes only). It removes only that plan's state: the retained worktree with its own admin entry, its `adopt-<digest[:12]>` branch and its failure record. It never runs `git worktree prune`, which would also drop the admin entries of other worktrees whose directories are missing and so change what a later plan reads. The owner's choice on a card that named the failure is the acknowledgement, and the console runs the cleanup in three places:

- on `Apply it again`, which passes `--discard-retained`;
- before any plan run of a root that leaves a failed apply's kept copy behind: a draft change, `Turn signed commits off`, `Register again` and `Try again`;
- on `Cancel registration` (D7).

A removal that fails is named as a failure with its next step, never left as an unnamed copy, so no note asks an agent to remove anything. This supersedes ADR-console-035 D7.

**D5. Turn signed commits off.** When the shown registration carries a drafted contract whose signing setting is `yes`, the failed-apply card for a signing failure offers `Turn signed commits off` beside `Apply it again` and `Not now`. It sends the existing draft change on `POST /api/plan-answer` (ADR-console-029, ADR-console-031) with the answer `no` for `commit-signed`, so the console plans again from the changed draft and writes nothing into the repository. The superseded plan's kept copy goes by D4. A committed contract's signing setting is the repository's own file, which the console never edits, so that card offers only `Apply it again` and `Not now` with the one-sentence signing step.

**D6. Paths and project ids break only after a slash.** A whitespace-free word that holds a `/` is drawn as `.seg` segments split after each `/`, with a `wbr` between them. `.seg` is an inline-block with `max-width: 100%` and `overflow-wrap: anywhere`, so a segment breaks only when it is longer than the line by itself. Every path-bearing label goes through it, including the folded draft pick buttons and the draft option buttons, and a card's ask uses `text-wrap: pretty` instead of `balance`. This extends ADR-console-035 D10.

**D7. Cancel registration.** `POST /api/register-cancel` is a member of `PAGE_WRITES` under ADR-console-008. Its body is one `application/json` object of at most 4096 bytes, exactly `{"root"}`, a non-empty string with no character below 0x20 and no 0x7F; any other body is `400` `bad registration cancel`. Refusals on the merits are `409` with the reason, append nothing and run nothing: a run under way, a root that is not the shown registration's, and a registration whose plan was applied (an applied, pushed or opened adoption). Otherwise, when the plan's apply failed and a kept copy exists, the console runs the D4 discard first, and only then; a discard that fails is a `409` that names it. It then appends one `registration.cancelled` row `{"by": "owner", "root", "plan_id"}`, which is not a kept kind (ADR-console-009), and answers `204`. The registration, deferral, adoption and folder-trust folds each drop what the row names, so registering the same repository again, which plans to the same content-addressed plan id, starts clean with a fresh `Apply it` and no stale `Check again` card. The page offers `Cancel registration` as a button in the Work box under the one line, not as a card option, because it must exist where no card does (after `Not now`): while the registration is done, its result is not `registered`, no run is under way and its plan's adoption is absent or failed at apply. It is never offered once apply succeeded. It grants no trust, writes nothing into the repository or the profile files, and runs only the D4 discard.

**D8. Stored words are read in the new words.** The flow is live, so rows stored with the replaced words are read in the new ones: the adoption notes through `approve.LEGACY_WORDS` and `approve.current_note`, and a registration's stored manifest step through `register.LEGACY_NOTES` in `register.latest`. No row is rewritten in the log. This supersedes ADR-console-035 D11.

## Consequences

- The Work column shows one sentence per registration and at most one control, `Cancel registration`; every other way out is a card option.
- A failed apply is retried with `Apply it again` with no manual cleanup, and no note names a leftover copy, a path, a branch or a hash.
- The adoption tool gains one targeted, acknowledged cleanup and still never prunes, so other worktrees and the plan's input digest are untouched.
- The write guard's set grows by one member, `POST /api/register-cancel` (ADR-console-008), which appends one row and reads and writes nothing else.
- Tests keep checking every card and Work text against the pattern of ADR-console-035, with `just switch` the one command allowed.
- Amends ADR-console-035 (D3, D5, D7, D8, D10, D11), ADR-console-008 (the page-write set) and ADR-console-030 (D5, D9).
- Related: ADR-console-008, ADR-console-029, ADR-console-030, ADR-console-031, ADR-console-035.
