# ADR-console-105 — A long command's permission card opens with a summary read from its text

A manager's permission card showed a 15,553-character heredoc verbatim, so the owner read all of it to learn what it wrote, ran and reached outside the project (#1621, per ADR-console-100 D10). The console now computes a summary from the command text alone, with no model call, file read or subprocess, and the card opens with it and folds the full text when the command has more than 200 characters or more than three lines; a short command keeps its card and carries no summary. The summary lists the files the command writes, the programs it runs and a warning for any path outside the manager's own project root (ADR-console-103 D3), a path the text cannot place counting as outside. It reads simple commands, redirections and here-documents, and says it could not read anything else, never a partial summary. Standard input reaching a program not on a closed allowlist of data readers is a script that program may run, and over-warning is accepted. The write list is only what the console recognises, so the card never says no file is written. The summary decides nothing: Allow once still allows the whole command (ADR-console-100 D2).
