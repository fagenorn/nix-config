# ADR-console-106 — A manager reruns a failed required check on its own pull request, at most twice per head

Three managers waited for the lead to rerun one failed job each, because the permit refused every failed-job rerun of a pull request run: it counted each job whose conclusion was not success, and the push-only Suite Timing Baseline job is skipped on every pull request run and is not a required check (#1712, per ADR-console-094). ADR-console-094 stays: the grant is the permit hook with no allow rule and no bypass. Two parts of the rerun rule change. The jobs a rerun would run no longer include a skipped job whose own `if` can never hold for a pull request event, read from the run's workflow file at its head and proved only for a `&&` chain with a `github.event_name` test for another event and no `||`, so anything the reading cannot prove still counts and an unreadable workflow file is a refusal. And a head is rerun at most twice: the permit counts the allowed reruns of the head from its own `permit.judged` rows, refuses the third naming the two reruns by run and failing suite members, and a new head starts at zero. Each allowed row carries the run, pull request, head, count and the `suite-runner: failed <member>` lines of the failed jobs' logs, evidence only. A run that is not a pull request run, a Deploy run included, stays refused.
