# ADR-console-106 — A manager reruns a failed required check on its own pull request, at most twice per head

Three managers waited for the lead to rerun one failed job each, because the permit refused every failed-job rerun of a pull request run: it counted each job whose conclusion was not success, and the push-only Suite Timing Baseline job is skipped on every pull request run and is not a required check (#1712, per ADR-console-094). ADR-console-094 stays: the grant is the permit hook with no allow rule and no bypass. Only two parts of the rerun rule change. The jobs a rerun would run no longer include a skipped job whose own `if` can never hold for a pull request event, read from the run's workflow file at the run's head and proved only for a `&&` chain with a `github.event_name` test for another event and no `||`, so anything the reading cannot prove still counts and a workflow file that cannot be read is a refusal. And a head commit is rerun at most twice: the permit counts the allowed reruns of the head from its own `permit.judged` rows, refuses the third with a sentence that says the head has been rerun twice, names the two reruns by run and failing suite members, and says the head must be reported or fixed, and a new head starts at zero. Each allowed rerun's row carries the run, the pull request, the head, the count with this rerun and the failing suite members, the `suite-runner: failed <member>` lines of the logs of the run's failed jobs, which are evidence only, so a log that cannot be read leaves them empty and refuses nothing. A run whose event is not a pull request, a release commit's Deploy run included, stays refused; the retention window of the event log bounds the count's memory, and two managers racing for one head end in the console's second judgement refusing the later one as moved.
