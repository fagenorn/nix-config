# ADR-console-066 — A named colleague reaches the console only through Tailscale Serve on a guest port

Context: the owner wants to share the console with one named colleague, but whoever loads the owner's page is the owner (ADR-console-008, #1235). Decision: Tailscale Serve proxies to a guest door of its own, never the owner's port; a guest request needs the configured tailnet name (`<host>.<tailnet>.ts.net`) and exactly one login header naming a listed colleague, gets a guest token of its own and records who acted; releases, spend, accounts, activation, registration, the access list, stopping a sprint, every manager route, a look before merge and an `owner_only` question stay the owner's; the owner's port refuses Tailscale identity headers and `X-Forwarded-For`. A local process that forges the header gains nothing it lacked. Rejected: trusting the identity header on the owner's port, Funnel, which is public, and Tailscale inside WSL.
