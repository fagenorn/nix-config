# ADR-console-008 — Only the page writes, with a per-install token and the console's own origin

- **Status:** accepted; amended by ADR-console-024, ADR-console-025
- **Decided in:** #837, #838, #861, #862, #886, #887, #889, #891, #1026, #1027, #1035

## Context

ADR-console-004 gave the console one write route, the hook route, which appends session observations and answers nothing, so it carries no token. The page's digest of what changed since the owner last looked (#861) needs the page to write: the console, not the browser, stores when the owner looked (#837 item 8). A write the page makes can change what the owner is told, so any local process or foreign web page must not be able to make it. #838 item 7 decided that page writes need a per-install token and an origin check.

## Decision

A write made by the page is a page write, and the only paths that take one are the members of `PAGE_WRITES` in `agent_tools.console.service`. Every member goes through one guard, `_page_write`, and a later write joins the set rather than adding a route of its own. The first member is `POST /api/looked`, which appends one `page.looked` event and answers an empty `204`; the second is `POST /api/answer` (ADR-console-010), which ticks a decision prompt on the tracker; the third and fourth are `POST /api/goal` and `POST /api/withdraw` (ADR-console-011), which state and withdraw a goal in the console's own log; the fifth and sixth are `POST /api/approve` and `POST /api/reply` (ADR-console-013), which approve a manager's brief or ask it for changes; the seventh is `POST /api/message` (ADR-console-016), which stores the owner's message to a sprint; the eighth is `POST /api/round-answer` (ADR-console-019), which answers one question of a manager's round; the ninth to eleventh members are `POST /api/signin`, `POST /api/signin-code` and `POST /api/signin-cancel` (ADR-console-024), which start, pass a code to and cancel a profile's sign-in; the twelfth member is `POST /api/account-add` (ADR-console-025), which adds an account profile and starts its sign-in; the thirteenth member is `POST /api/signin-link` (ADR-console-024), which answers the link of a profile's running sign-in. `POST /api/brief`, `POST /api/report`, `POST /api/inbox`, `POST /api/message-reply` and `POST /api/ask` are not page writes: they are the manager's writes, guarded by the sprint's secret under ADR-console-013, ADR-console-014, ADR-console-016 and ADR-console-019.

The guard admits a page write only when exactly one `Origin` header equals `http://<Host>`, the console's own origin, and exactly one `X-Console-Token` header equals the install's token, compared in constant time. It runs after the loopback `Host` check and before any body is read, so a refused write reads nothing and appends nothing. A terminal sends no `Origin` and a foreign page sends its own, so neither passes. The body rule is per route. `/api/looked` carries no body: a `Content-Length` other than absent or `0`, or any `Transfer-Encoding`, is refused as `400` `no body`. `/api/answer` carries one `application/json` body of at most 4096 bytes, read only after the guard admits the request: any `Transfer-Encoding` or a `Content-Length` that is not digits is `411`, another media type is `415`, a longer body is `413` with the body unread, and a body that is not the expected object is `400` `bad answer`. `/api/goal` and `/api/withdraw` carry the same kind of body under the same `411`, `415` and `413` rules, with limits of their own: `/api/goal` at most 16384 bytes and `/api/withdraw` at most 4096 bytes. `/api/approve` carries at most 4096 bytes and `/api/reply` at most 16384 bytes, with the same `411`, `415` and `413` rules; a body that is not the expected object is `400` `bad approve` or `400` `bad reply`. `/api/round-answer` carries at most 16384 bytes under the same rules; a body that is not the expected object is `400` `bad round answer`, and a refusal on its merits is `409` with the reason. A body that is not the expected object is `400` `bad goal` or `400` `bad withdraw`, and a write the console refuses on its merits is `409` with the reason. The three sign-in writes carry at most 4096 bytes each under the same `411`, `415` and `413` rules; a body that is not the expected object is `400` `bad sign-in`, `400` `bad code` or `400` `bad cancel`, a refusal on its merits is `409`, and the start alone answers `200` with the attempt and the link (ADR-console-024). `/api/account-add` carries at most 4096 bytes under the same rules; a body that is not the expected object is `400` `bad account`, a refusal on its merits is `409` with the reason, and it answers `200` with the attempt, the link and the profile (ADR-console-025). `/api/signin-link` carries at most 4096 bytes under the same `411`, `415` and `413` rules; a body that is not the expected object is `400` `bad link`, a refusal on its merits is `409`, and it answers `200` with the attempt and the link; it appends nothing (ADR-console-024).

The token is 43 URL-safe characters, created once in `page-token` beside the event log (mode 0600, directory 0700, created with `O_EXCL`) and read back on every start. A token file that is unreadable or malformed stops the console, with `console: page token unusable: <error>` and exit 1. The token is placed in the page's `console-token` meta tag when the page is served and appears in no API answer, stream frame, log row or stderr line.

## Consequences

- A local process can read the token from the page or from the file: loopback trust is the boundary (#826), and the token only stops a foreign page and a request that did not come from the page.
- A page served before a restart keeps working, because the token belongs to the install and not to the run.
- The hook route stays tokenless, as ADR-console-004 decided.
- Deleting `page-token` makes the next start mint a new token; a page still open from before shows a `403` on its next write until reloaded.
