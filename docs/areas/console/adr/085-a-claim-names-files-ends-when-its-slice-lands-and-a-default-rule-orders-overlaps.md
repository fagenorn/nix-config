# ADR-console-085 — A claim names files, ends when its slice lands, and a default rule orders overlaps

Context: a claim notice (ADR-console-044) named a whole folder tree and outlived its slice, so every slice another sprint cut there was an overlap and each one went to the owner as a question card, though most were two features touching the same files, which a fixed order settles (#1337, #1347). Decision: a claim names files or a narrow path relative to the project's root (no folder tree, absolute path or `..`), its slice's `issue` and optionally `live_fault`, and ends when the sprint's report lists that issue landed or held; two overlapping slices are ordered by a default rule, a live-fault fix before a feature, else the earlier-started first, and the second rebases; two live-fault fixes are the one overlap the rule cannot settle, shown as one line on the owner's page under the two sprints, never a card, and both sprints keep working and follow an owner's heads-up that states the order; nothing is refused for a claim. Rejected: a free-text area the console cannot compare, a question card for every overlap, and a card from one asking sprint for the unsettled one.
