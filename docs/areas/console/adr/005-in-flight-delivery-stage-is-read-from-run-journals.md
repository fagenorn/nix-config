# ADR-console-005 — In-flight delivery stage is read from run journals

Context: the owner cannot tell a planning run from a landing one, and Workflow journals carry no time (#830). Decision: each run's stage is read incrementally from its journal.jsonl through label tables bound to the delivery programs, and a run moved when its journal's mtime says so. A run line of a running sprint's issue reads that sprint's movement for the issue (its journal, that issue's waits, its own session's output and running check) and, while only a wait moves it, ends with that wait (#1212). Rejected: reading stalled from a quiet journal, because a slow step and a dead one look the same (#837); and a run line on the journal alone, which contradicted its sprint line about one issue. The trade-off is that the console is coupled to the programs' label names, and a test holds that coupling. Superseded for an engine run, which keeps no journal and is read from its run ledger (`agent_tools.console.engine_runs`).
