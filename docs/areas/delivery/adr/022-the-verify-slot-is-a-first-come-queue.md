# ADR-delivery-022 — The verify slot is a first-come queue

Waiters for a verify slot are served in arrival order, every live waiter before every ordinary one, which amends the no-order clauses of ADR-delivery-014 D8 and ADR-delivery-016 D6; a run in progress is still never preempted (ADR-delivery-014 D3). A waiter joins by creating a numbered ticket file in the slot directory under an exclusive `flock` on `queue.lock` and holds an exclusive `flock` on its ticket while it waits, so a waiter killed by SIGKILL leaves the queue at once and no daemon keeps the order. Free slots go one at a time, in that order, to the waiters whose repository holds fewer slots than its declared limit (ADR-delivery-023); a waiter its repository holds back, live or not, keeps its place, gets no priority and blocks no one. A run that reaches `--wait-limit` leaves its ticket reserved, and the same argv run in the same working directory takes it back while the reservation is under 300 seconds old or a later waiter still waits. A waiter prints its place and the slots' holders whenever either changes, and the history line records the place it joined at. Rejected: a queue daemon, which every account would have to start, keep alive and trust; and blocking `flock` waits, which promise no order and hold no wait limit.
