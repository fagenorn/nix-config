# ADR-delivery-024 — A new test is a unittest id the merge base lacks, run alone in a scratch worktree at the merge base

The `revert-check` step (issue 1534) needs to tell new tests from source and to run one test; no decision fixed either. A new test is a `test*` method of a top-level class that reaches `TestCase` through classes of its own file, in a `.py` file the change adds or modifies, whose id `<module>.<Class>.<method>` the file at the merge base lacks; every other changed file is source. The check checks the merge base out into a scratch directory (no registered worktree), writes the head version of each file holding a new test over it, refusing a symlink, and runs each new test once as `python -m unittest <id>` from the scratch root, each on a fresh checkout. The path puts the scratch root, then the parent of each top-level package tracked there, ahead of the inherited `PYTHONPATH`, whose entries inside the run's worktree are dropped, so the reverted source is what the test imports. Exit 0 is a test that still passes. This fits the engine fixture project and this repository, both Python `unittest`; another stack's tests are not recognised, so such a change lists none. Rejected: the implementer's reply naming its tests (a claim, not a reading of the diff), a per-test command in the project contract (no binding exists) and running whole changed test files (old tests would count as new).
