# ADR-delivery-025 — Engine agent steps run with permissions skipped and the lifecycle guard is their one control

The engine launched each agent step under `dontAsk` with shell allow and deny rules of its own per role, and a read-only step was denied an ordinary read pipeline, so a real run ended in setup; each fix of those rules missed another shape a shell accepts. The owner ruled: "Yes, please stop reinventing the permission system." and "In regards to the permission mode in general, we allow dangerously-skip-permissions - this is how you are running, and it isn't causing issues." So every engine agent step launches with `--dangerously-skip-permissions`, and the PreToolUse lifecycle guard hook, still loaded in every session, is the one control over push, pull request creation, merge, branch deletion, release and detached processes. The engine has no permission layer of its own: no allow or deny rule, no read-only shell pattern, no code that parses or admits a role's commands, and it refuses a role file naming a scoped rule. A role's tool list may still leave out tools it has no use for. A call Claude Code itself refuses is asked about once more on the same session, unless a bound or an API failure ended it, and a second refusal stops the run at `tool-denied`. Rejected: a read-only allow list under `dontAsk`, which refused ordinary reads, and one plain command per call enforced by the guard, an engine rule in a shared guard.
