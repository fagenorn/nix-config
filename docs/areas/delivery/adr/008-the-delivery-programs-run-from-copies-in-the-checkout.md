# ADR-delivery-008 — The delivery programs run from copies in the checkout

The lead started `deliver-batch.js` and its `deliver-standard.js` children by skill-directory paths that reach the Nix store through links, so an activation during a batch left the next child unloadable, and the Workflow tool reads the child program from its path at every child launch, so a copy replaced in place gave a running batch children of a newer version. So `program-copies` places the programs in `<checkout>/.program-copies/<skill dir name>/<set>/`, ignored by git, where `<set>` hashes every program's name and bytes: a set is never changed once placed, a lead takes both paths of one launch from one output, and a set last used more than 24 hours ago is pruned. Copies under the git common dir were rejected because a linked worktree's git directories lie outside its working directory, where the Workflow tool refuses a script path; per-run copies with no pruning because they grow without bound; keeping only the newest few sets because the safe count depends on how many host switches fall inside one batch (decided in issues 912 and 981).
