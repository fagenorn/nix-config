# ADR-delivery-023 — Each repository declares its verify slot limit in the host declaration

The number of one repository's `verify-slot run`s that may hold verify slots at once is host policy: the host declaration's optional `verify_repository_slots` member maps a lowercased `owner/repo` to a positive integer, and a repository it does not name keeps 1, which amends the repository limit of ADR-delivery-022 and keeps its first-come order, live priority and freeing on SIGKILL. A waiter writes its repository's limit into its ticket when it joins, and every waiter is judged by the limit in its own ticket, a ticket without one by 1, so runs that read different declarations, before and after an activation, still agree on who goes next. A repository whose suites share a resource, such as one test database, keeps 1; one whose runs share only CPU may declare more, and the number changes only when the host is activated. Rejected: one limit for every repository, which holds every repository to the one with a shared database; a limit in each repository's own contract, which lets a repository raise its own claim on a shared host; and each run applying its own reading of the declaration to every waiter, under which two readings can each name another waiter next while a slot stays free.
