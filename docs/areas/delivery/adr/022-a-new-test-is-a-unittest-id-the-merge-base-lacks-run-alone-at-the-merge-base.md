# ADR-delivery-022 — A new test is a unittest id the merge base lacks, run alone in a scratch worktree at the merge base

The `revert-check` step (issue 1534) needs to tell a change's new tests from its source and to run one test, and no decision fixed either. A new test is a `test*` method of a top-level class that reaches `TestCase` through classes of its own file, in a `.py` file the change adds or modifies, whose id `<module>.<Class>.<method>` (the file's path with `/` read as `.`) the file at the merge base lacks; every other changed file is source. The check adds a detached scratch worktree at the merge base with hooks off, writes the head version of each file holding a new test into it and runs each new test once as `python -m unittest <id>` from the scratch root. The path puts the scratch root, then the parent of each top-level package tracked there, ahead of the inherited `PYTHONPATH`, whose entries inside the run's worktree are dropped, so the reverted source is what the test imports. Exit 0 is a test that still passes. This fits the engine fixture project and this repository, both Python `unittest`; a test in another stack is not recognised, so such a change lists no new test. Rejected: the implementer's reply naming its tests (a model's claim, not a reading of the diff), a per-test command declared in the project contract (no binding exists, and every stack would need one) and running whole changed test files (their old tests would be listed as new).
