# ADR-delivery-021 — A rule whose enforcer can fix its violations gets a fix change

An enforcer may declare an autofix, and Ruff does for its fixable rules with safe fixes only, never unsafe ones. When the picked rule's autofix, run on exactly the files the listing bounds, changes files, the cleanup command opens one fix pull request on the integration branch in place of a cleanup issue. It carries the marker `<!-- agent:cleanup-fix v1 rule=<id> -->` and shares the one cleanup slot: an open cleanup issue or fix change by a trusted author holds it, and the command never closes one. An autofix that changes nothing falls back to the ordinary issue. Only a writer whose pull requests start the required checks opens a fix change, so the workflow token answers `deferred`, exits 0 and leaves the opening to the verify-pending pass, whose `cleanup-issue fix` step runs on each host with the owner's credential. The change goes through the API alone: a ref at the revision, one commit of the changed files and the pull request, and a ref another writer created answers `taken`. The workflow gains `pull-requests: read` to see fix changes and no write scope (amends ADR-delivery-017 D6). Rejected: the workflow token with `workflow_dispatch`, since the checks are bound to pull request events.
