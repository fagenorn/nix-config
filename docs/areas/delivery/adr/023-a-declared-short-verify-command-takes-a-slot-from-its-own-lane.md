# ADR-delivery-023 — A declared short verify command takes a slot from its own lane

A verify command the host declaration names short for its repository runs in a short lane apart from the verify slots: the optional `verify_short_lane` member gives the lane's slot count, a bound in seconds and, per lowercased `owner/repo`, the exact argvs that are short. A short run never waits behind a long run, of its repository or another, and skips the repository limit, which amends ADR-delivery-014 and ADR-delivery-022; each lane keeps its own first-come queue with live waiters first, and a live short waiter neither defers to nor holds back a long run. A short command still running at its bound has its process group sent SIGTERM and, after a grace, SIGKILL, and the run exits 124 with a line saying so, so the lane is never held long. Each history line records its lane, and short slots and tickets have names an older long-lane reader never lists. Rejected: skipping only the repository limit inside the shared slots, under which a lint still waits while every slot holds a suite; a flag each caller passes, which every caller would have to get right; and a short mark in each repository's own contract, which lets a repository claim a fast lane on a shared host.
