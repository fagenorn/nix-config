# ADR-delivery-004 — A code map is a navigation lead, never an authority

The design skill and the deliver-standard planner each leave a code map so the next agent need not rediscover the modules a change touches, but a map records what one agent read at one moment and goes stale. So a map is a lead: it is kept in the git directory of the worktree it was written in, never staged, committed, pushed or reviewed and measured by no artifact-budget kind; a plan never cites, links or copies it, and every mapped path and symbol a plan writes into a task is checked against the tree. Committing a map, or citing it from a plan, was rejected because a tracked or cited map would read as a decision; the price is that a map is lost with its worktree and a rerun of `design` overwrites it, while a stale entry costs a lookup, not a wrong plan (decided in #354 and #743).
