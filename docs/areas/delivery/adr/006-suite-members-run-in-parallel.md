# ADR-delivery-006 — Suite members run in their own processes, in parallel by default

The agent workflow suite is CPU-bound and its CPU time does not change with the job count, so only wall time can be bought. Each member runs in its own process, at most `--jobs N` at once and longest first in the order of the committed `suite_timings.json`; the default is `SUITE_RUNNER_JOBS` when set and non-empty, else `min(8, CPUs - 2)` with a floor of 1, so two CPUs stay free for the host and a large machine does not oversubscribe its disk and git, and a host shared by several verifying agents sets `SUITE_RUNNER_JOBS` lower. A test that shares state with another test process is fixed by giving it its own temporary location, never by a serial-exemption list, a retry or a lock. Running every member serially was rejected because a full run was then too slow to serve as the verification gate (decided in issues 436, 496, 499 and 604).
