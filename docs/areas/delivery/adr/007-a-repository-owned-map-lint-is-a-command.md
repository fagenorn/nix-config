# ADR-delivery-007 — A repository-owned context-map lint is a `context-map-lint` command

`context-map-lint` enforces one map budget and one default area budget for every repository; a repository that outgrew them ran its own copy of the lint in CI, and the machine-global tool and the grill-with-docs skill kept failing a map that lint accepted. Such a repository declares its lint as the `commands` entry with the id `context-map-lint`, an agreed name the resolver gives no meaning of its own; the caller that resolved the contract passes the entry's argv after `--repo-lint` and its `cwd` as `--repo-lint-cwd`, and the tool then runs none of its own checks and exits with that command's status. Budgets as a new contract member were rejected because they grow the schema for two numbers while a repository's lint may differ in rules too; the tool resolving the contract itself was rejected because it reads no project policy, which lets another project's CI call it at a stable path (decided in issue 873).
