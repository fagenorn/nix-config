# ADR-delivery-020 — Lint time is read from the Conformance job logs and filed as one issue

The Conformance run prints one stderr line, `lint-times v1 <json>`, when `conformance run --lint-times` ran a never-rise enforcer: each lint's wall milliseconds on the merge base and on the branch, and their sum, with the report and stdout unchanged. Only the own-tree form of the rendered workflow gains the flag, so no other project's workflow goes stale, and nothing is committed (amends ADR-project-contract-015 D3). The `lint-time` command reads the newest 50 completed `push` runs of `conformance.yaml` and takes the first 20 whose `Conformance` job log has a record; a missing job, a gone log or no line is skipped, and a malformed or doubled line exits 2 with nothing filed. The budget is breached when the median total is above 60 000 ms, and the slowest lint is the one with the highest median, ties to the id that sorts first. One open issue marked `<!-- agent:lint-time v1 -->`, trusted authors only and counted apart from the cleanup issue, is filed; the command never labels, comments or closes. `.github/workflows/lint-time.yaml` runs on `push` to `main` with `contents: read`, `actions: read` and `issues: write`, queues pushes in one non-cancelling group, is no required context and never fails a change. Rejected: an Actions artifact, facts in the report, committed timings and always-on stderr output.
